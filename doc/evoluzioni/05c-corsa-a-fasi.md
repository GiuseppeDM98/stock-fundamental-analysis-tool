## 1. Il problema oggi (prove, commit `b2281b9`, 2026-10-27)

1. **La Deep Value vive nel client fino a «Salva».** `components/deep-value-panel.tsx` › `handleGenerate` accumula lo stream in `accumulated`/`report` (`:160-170`) e `handleSave` (`:194-205`) chiama `saveAnalysis` (`lib/analyses.ts:11`) solo al click; `app/api/ai/deep-value/route.ts` non scrive nulla. Su Vercel Hobby (Fluid Compute) una function è fermata a 300 s qualunque cosa stia streamando: una run tagliata perde report e costo. La 02 esporta `maxDuration = 300` e porta il JSON in coda: un taglio lascia un report senza JSON, in silenzio.
2. **La lente Grounded fa due turni in UNA richiesta.** `app/api/ai/deep-value/verify/route.ts` esegue `turn1` (cieco, `:275-301`) e `turn2` (reconcile, `:353-394`) nella stessa function (`maxDuration = 300`, `:48`, con il commento che dichiara il limite); il client persiste con `PATCH /api/analyses/[id]` solo a fine stream (`components/analyst-panel.tsx:283-300`). La Fase 1 riuscita di una lente tagliata in Fase 2 si perde con tutto il resto, e «Run» ricomincia sempre dalla Fase 1.
3. **Lo stream è testo grezzo senza evento terminale** (`Content-Type: text/plain`, `Transfer-Encoding: chunked`, `route.ts:171-177`): il client riconosce solo lo stream vuoto (`deepValueEmptyResponse`, `deep-value-panel.tsx:172-179`); uno stream interrotto a metà diventa `done` con un report monco (`:183-185`). Niente distingue «finito» da «tagliato dalla piattaforma».
4. **Nessun «Riprova dalla fase».** Ogni errore riparte da capo, anche quando la fase prima (dataset dello stadio 1, Fase 1 della lente) è già persistita.
5. **Nessuna durata per fase è registrata nel repo**: la run reale del 2026-10-29 (commit `18d7f27`, Opus 4.8 `xhigh`: Deep Value 708 s, Scettico 510 s, una richiesta ciascuna; `CLAUDE.md § Known Issues`) e la 05a A6 registrano la durata della run intera (la 05a con `durationMs`), la 05b A8 e la 08b nessuna; oggi nessun log la stampa (`[tool-loop]` logga solo l'usage per round).
6. **Il riferimento già in esercizio altrove**: il Consulente di net-worth-tracker (`app/api/allocation-advice/run/route.ts`, `components/allocation/consulente/useConsulenteRun.ts`, `doc/guide/consulente.md § La corsa`, 2026-10-20/23) — una richiesta per fase con `maxDuration = 300`, il documento scritto dal server a ogni fase, SSE `stage | done | error`, `resumeFrom` con «Riprova» dalla fase fallita, corsa stantia a 20 minuti, partenza dal click e mai da un effetto. La corsa intera era 396 s in una richiesta; divisa, ogni fase sta nel tetto. La lettura del 2026-10-27 ha confrontato ogni pezzo con quel codice: le differenze volute sono dichiarate in § 3 (D-84, D-85, D-88, D-96) e le lezioni che quel repo ha pagato sono riportate in § 5.

## 2. Obiettivo e criteri di accettazione

Ogni chiamata al modello è una richiesta HTTP a sé, ≤ 300 s, il cui risultato è scritto dal server appena arriva; il client incatena le richieste e riparte dalla fase rimasta a metà. Nessun prompt cambia: la Fase 2 delle lenti cambia COME i prompt esistenti vengono composti nei `messages` (D-83), non il loro testo.

## 4. La soluzione

### 4.1 Schema e DDL

`prisma/schema.prisma` › `Analysis`:

```prisma
  // The run that produced this row (2026-10-27): on Vercel Hobby a function is stopped at
  // 300 s, so the row is created when the valuation starts and finished by the server, never
  // by the client. "running" past RUN_STALE_AFTER_MS without an update means the platform cut it.
  runStatus     String    @default("done")
  runStartedAt  DateTime?
  runError      String?
```

Migrazione `add_analysis_run_status` (quattro `ALTER TABLE "Analysis" ADD COLUMN …`, nessuna ricostruzione; `runStatus TEXT NOT NULL DEFAULT 'done'`, `priceCurrency TEXT` nullable): si applica a Turso PRIMA del deploy — il codice vecchio ignora le colonne, il default `done` copre ogni riga esistente (T-19, ordine globale delle migrazioni: dopo la 04).

### 4.2 Moduli puri

## 5. Vincoli e trappole

- **Vercel uccide senza `finally`**: una fase oltre i 300 s lascia `running`; nessun codice può scrivere `failed` in quel momento. Il pannello che ha visto il taglio riprova dopo 330 s (D-85); /analyses la dichiara «interrotta» a 20 minuti (T-36); il log `[ai-run]` manca proprio nelle run che interessano a D-77: la misura della fase tagliata è `runStartedAt` vs l'ora della kill nei log di Vercel.
- **`after()` di Next non aiuta**: gira dentro la stessa function e lo stesso tetto.
- **Fluid compute deve essere acceso** (Vercel → Project → Settings → Functions): senza, il tetto è 60 s e ogni fase è tagliata (`route.ts:21` del Consulente). Controllo in § 8.
- **Un `enqueue` su uno stream cancellato lancia** (`TypeError`, WHATWG Streams): con il client andato via, l'eccezione nascerebbe dentro `onTextDelta`, risalirebbe dal `for await` del loop e porterebbe nel `catch` una corsa che andava bene. Per questo ogni invio passa da `createSseChannel` (T-40) e il server finisce la fase (D-84).
