# Valuation — Deep Value, analyst panel, Grounded mode, AI providers

The domain guide for everything that produces, stores or reads a valuation. AGENTS.md keeps a short stub with the hard invariants; this file keeps the detail. Most of it moved here from AGENTS.md on 2026-10-29, when the output contract changed to research first, report, JSON last.

Files: `lib/ai/deep-value-prompts.ts` (prompt builders), `lib/ai/research-*.ts` + `lib/ai/transcript-urls.ts` + `app/api/ai/research/route.ts` (the research stage), `app/api/ai/deep-value/route.ts` and `app/api/ai/deep-value/verify/route.ts` (the two streaming routes), `lib/ai/stream-gate.ts`, `lib/report/parse-deep-value-json.ts` (parser, sanitizer, markers), `lib/report/deep-value-run.ts` (the save request), `components/deep-value-panel.tsx`, `components/analyst-panel.tsx`, `app/analyses/[id]/page.tsx`, `lib/analyses-select.ts`, `lib/grounding/*`, `lib/datasets/*`, `components/dataset-section.tsx`, `lib/ai/*` (client, tool loop, preferences), `types/ai-settings.ts`, `components/report/*`.

## 1. The output contract

### 1.1 Order and markers

- **Deep Value**: the model does ALL its research (every web search) first, then writes the exact line `<!--report-->`, then sections 1–10 with no tool call and no search commentary, then the JSON block as the very LAST thing, nothing after its fence (Step 4 of `buildDeepValueSystemPrompt`). **Lenses**: `<!--critique-->`, the critique, the JSON last. Why (2026-10-29): the JSON restates numbers the report has already argued, so text and numbers stay coherent, and the stream is readable from the first heading instead of opening with a JSON blob.
- The markers are sentinels independent of language and section numbering: `REPORT_START_MARKER` / `CRITIQUE_START_MARKER` in `lib/report/parse-deep-value-json.ts`, interpolated into the prompts, so prompt, gate and strip share one source. They never reach the page: react-markdown 10 renders an HTML comment as visible text (`&lt;!--report--&gt;`, verified 2026-10-29), so the route's gate drops the marker and `stripJsonBlock` strips any repeat.
- The blind Phase 1 of a Grounded lens is unchanged: JSON first, relabelled ` ```json-blind ` by the server (§ 3.2).
- **Known prompt defect** (2026-10-29): the closing disclaimer is an English literal in the "Close section 10 with the line" and "Close the critique with the line" rules, so an Italian report or critique ends in English although the prompt asks for every word in the report language. The Quick golden (§ 4) blocks a prompt-text fix until it is replaced; the fix then is to ask for the disclaimer in `${language}`.
- **Older reports** (saved before 2026-10-29) carry the JSON at the TOP. `parseDeepValueJson` reads the LAST ` ```json ` fence, which in those reports is the only one, so both formats parse with no branch. The e2e seed keeps `e2e_an_panel` in the old format on purpose: it is the compatibility fixture.

### 1.2 The JSON block, field by field

Type `DeepValueResult` (`components/report/types.ts`); a lens adds `AnalystResult`'s fields. Nothing in it is trusted: `sanitizeDeepValueResult()` keeps only known keys with the right types.

| Field | Meaning | Sanitizer / save |
|---|---|---|
| `method` | primary method: `DCF`, `DDM`, `EV/EBITDA`, `P/E`, `P/B`, `SOTP`, `EV/RAB`, `NAV`, `Residual Income` (`METHOD_LIST`, same list in the report and every lens) | string; saved truncated to 40 characters |
| `sector` | free text, max 80 characters | string; saved truncated to 80 |
| `currency` | ISO 4217, 3 letters | string; the column is written only when it matches `^[A-Z]{3}$` |
| `units` | scale of every monetary figure in the bridges: `billions` / `millions` / `thousands` / `units`; shares on the same scale; per-share values are plain currency | one of the four, else dropped |
| `bull` / `base` / `bear` | `{ fairValue, probability?, bridge? }`; `fairValue` is the MoS-adjusted BUY TARGET (§ 1.3) | a scenario without a finite `fairValue` is dropped, so `hasFullTriple` fails |
| `….bridge` | `{ driver, driverValue, driverYear, multiple?, netDebt, minorities, shares, intrinsicPerShare }`, PRE-MoS; asked in every mode since 2026-10-29 (Grounded only before) | numeric fields must be finite |
| `assumptions` | `{ wacc, roic, terminalGrowth }` in PERCENTAGE POINTS (8.5 = 8.5%); `roic` on invested capital, not ROE | a value outside [−50, 100] becomes `null` (catches 0.085 and 850) |
| `crossCheck` | `{ method, intrinsicPerShare, reconciliation, bridge? }`: the mandatory second method, base scenario, pre-MoS; its bridge omits `intrinsicPerShare` | |
| `sensitivity` | `{ leverA, leverB, intrinsicPerShare }`: two levers with three values each and a 3×3 grid, rows = leverA, columns = leverB, centre = the base intrinsic value | two named levers with three finite values each and nine finite cells, else dropped; `sensitivity_center` checks the centre and the monotonicity (§ 5.1); absent in lens blocks |
| `dividends` | `{ policy, lastDps, path }`: the latest complete year's ordinary DPS (interim + final, specials excluded) and three years of bull/base/bear DPS, annual totals on the same basis, or `null` for a non-payer. The prompt states that basis only for `lastDps` ("then project the annual DPS"), so for the path it is implicit until the prompt can change (§ 4) | `null` stays `null`; malformed → dropped (undefined: older reports, lenses) |
| `killPrice`, `killPriceNote` | Skeptic only: the price below which the thesis is dead; `null` only with a note | `null` kept when the key is present |
| `revisions` | blind-first lenses only: `{ scenario, from, to, reason }[]`, empty = no revision | |

### 1.3 Rules the code relies on

- **The MoS trap.** Stored `Analysis.fairValue{Bull,Base,Bear}` (and every `*FairValue*`) are **MoS-adjusted buy targets**: `intrinsic × (1 − mosPercent/100)`. The intrinsic value is NOT stored separately; reconstruct it with `grossUpToIntrinsic()` (`lib/report/valuation.ts`, never reimplemented): `intrinsic = stored / (1 − mosPercent/100)`. When `mosPercent = 0`, stored = intrinsic. The bridge's `intrinsicPerShare` is PRE-MoS, so `lib/grounding/postcheck.ts` grosses `fairValue` up before comparing: a direct comparison makes every check fail silently, always. It matters anywhere a value is shown or compared as "fair value": the exit signal threshold, `computeEvolution` (`lib/report/evolution.ts`), any label that says "Fair Value" vs "Buy Target".
- **The bridge rule** (`BRIDGE_RULE`, under every JSON template): the bridge always reads (multiple × driverValue − netDebt − minorities) / shares, or `intrinsicPerShare` directly when `multiple` is omitted. Equity-value methods (P/E, P/B, Residual Income, DDM, DCF on FCFE) declare `netDebt: 0` and `minorities: 0`; SOTP, NAV and EV/RAB give the summed enterprise value as `driverValue` with no multiple.
- **Narrow before dereferencing.** The parser returns `ParsedAnalystResult`, whose bull/base/bear may be missing: call `hasFullTriple()` first. An incomplete triple shows `deepValueIncompleteJson`, saves null fair values and no `resultJson` — never half a valuation. A malformed block still fails `JSON.parse` as a whole (CLAUDE.md, Known Issues).
- **The server re-sanitizes.** `sanitizeResultJson(text)` (parse → sanitize → `hasFullTriple` → `JSON.stringify`, or `null`) runs in POST and PATCH; what is stored is the server's re-serialization, not the client's text. Its key order is the sanitizer's.

## 2. Deep Value

### 2.1 The route — `/api/ai/deep-value`

- **Settings**: `resolveAiSettings()` (§ 6.2). When the request names no effort, the route applies `deepValueDefaultEffort(model, effort)`: the higher of the user's global default and `xhigh`, clamped down to what the model supports. An explicit effort in the request wins, also without a model: it then applies to the stored model (before 2026-10-29 an effort-only body was dropped; the Advisor route had the same drop).
- **Prompts**: `buildDeepValueSystemPrompt` / `buildDeepValueUserPrompt`, with `currentDate` from `new Date()` on the server. `dateClauseFor()` states today's date as the only source of "now" and derives the year from it (no hardcoded year: the model otherwise anchors to its training year). The analysis is **position-blind** (§ 2.6).
- **Stream gate**: `createStreamGate(REPORT_START_MARKER)` (`lib/ai/stream-gate.ts`) buffers everything until the marker, forwards only what follows, and handles a marker split across chunks. After the loop, `flush()` forwards the buffer if the marker never came and logs `[deep-value] report marker never arrived; flushed <length>`. The client treats an empty response as an error (gotcha #26).
- **`stop_reason`**: on `max_tokens`, if the forwarded text ends inside an open ` ```json ` fence, the route closes it (`\n```\n`) before the visible truncation note, so the client never parses half a block as a whole one. `max_tokens: 64000`; thinking and web search count toward it (a real Opus 4.8 xhigh run on 2026-10-29 used 47k).
- **Header `X-AI-Settings`**: the resolved `{ model, effort, thinking }` as JSON on the response, read by the client for the save (§ 2.3). `thinking` is `buildThinkingParam(...).type !== "disabled"`, so Sonnet 5.5's `between_tools` (its "off" below `xhigh`) records `true`; model and thinking are those resolved before the call, so a run answered by the Sonnet 5.5 refusal fallback still records `claude-sonnet-5-5` (the fallback note in the text names who answered). The verify route sends the same header and nothing reads it: a lens has no metadata columns.
- **`maxDuration = 300`**, the Vercel Hobby ceiling. The 2026-10-29 real runs took 708 s and 656 s locally: on Hobby they would be cut (CLAUDE.md, Known Issues). Measured cost of one Quick run at `xhigh` (2026-10-29): 480k input + 45k output tokens and 26 searches, about $3.8; one lens on it about $2 (243k + 27k, 17 searches).

### 2.2 The panel — `components/deep-value-panel.tsx`

- The initial `aiSettings` already carry the `xhigh` floor, so a Generate before `fetchAiSettings()` answers (or after it fails) still runs at `xhigh`; the fetched default goes through the same floor. The user can change it in `<AiSettingsControl>`.
- While streaming, the body renders `stripJsonBlock(stripTrailingOpenJsonFence(report))`: an open fence at the end is hidden, so no raw JSON flashes on screen.
- **Parse on the client, after streaming completes**, with the shared `parseDeepValueJson` / `stripJsonBlock`. **`mosPercent` comes in as a prop** (it was once hardcoded to 0).
- The run's inputs (`DeepValueRunInputs`: ticker, MoS, price, currency, language, `aiSettingsResolved` from `parseResolvedAiSettings(header)`, `null` when the header is missing or malformed) are frozen at Generate, so a later change of the slider does not alter what Save writes.

### 2.3 Persistence

- **Columns on `Analysis`**: `resultJson` (the sanitized final JSON), `currency`, `sector`, `reportLanguage`, `aiModel`, `aiEffort`, `aiThinking`, and per lens `reviewResultJson` / `optimistResultJson` / `qualityResultJson`; all nullable (migration `add_analysis_result_json`, additive, not repeatable: `ADD COLUMN` fails if the column exists). The scalar `fairValue*` and `valuationMethod` stay, and stay what consensus, ruler, watchlist and digest read.
- **Save** (`buildSaveAnalysisRequest`, `lib/report/deep-value-run.ts`): `resultJson` only with a full triple; method truncated to 40, sector to 80, currency only when it is a 3-letter code; model/effort/thinking from the header. `POST /api/analyses` validates with Zod (`resultJson` ≤ 30,000 characters, `aiModel` and `aiEffort` as enums), answers 400 `"resultJson must carry bull/base/bear"` to a block without a full triple, and stores the re-sanitized blob.
- **Lens PATCH** (`PATCH /api/analyses/[id]`, `{ angle, critiqueMd, fairValue*, valuationMethod, resultJson, blindJson? }`): an absent field leaves its column untouched; `null` writes `null`. The panel always sends the triple and `resultJson` as values or `null`, so a run without a full triple clears the lens's numbers together.
- **Selects** (`lib/analyses-select.ts`): `ANALYSIS_LIST_SELECT` lists every `SavedAnalysis` key, `as const satisfies Record<keyof SavedAnalysis, true>` — a key missing from either side breaks `npm run typecheck` (gotcha #20 is the silent version of this). `ANALYSIS_SUMMARY_SELECT` is the same minus the ten text blobs (report, the three critiques, the three blind and the three lens result JSONs) for the digest and other readers that only need numbers; the excluded fields come back `undefined` (not `""` or `null`), so a reader that needs `reportMd` — the last-fence fallback of a row without `resultJson` — queries it separately. `__tests__/analyses-contract.test.ts` pins both lists. **Mirror any new persisted field across all contract points**: Zod (POST/PATCH), `types/analysis.ts`, `ANALYSIS_LIST_SELECT`, `ANALYST_COLUMNS` (`lib/report/consensus.ts`) for a lens column.
- **`Analysis.datasetId` is in `SavedAnalysis` and the list select; `Analysis.groundingJson` is deliberately outside both**: legacy and read-only (§ 5.2), a blob the list never uses. The comment on the type says so; read it before "restoring" the field.

### 2.4 The saved detail page — `app/analyses/[id]/page.tsx` + `components/analysis-detail-body.tsx`

The server page reads the row and the open lots (aggregated into one position) and hands them to the client `<AnalysisDetailBody>`. The summary (badges, cards, recap) comes from `resultJson` when the column is set, else from the last fence of `reportMd`; `hasFullTriple` decides whether the summary, the checks card and the analyst panel render at all (no triple → the banner and the plain Markdown body, no quote fetch). The body is `stripJsonBlock(reportMd)`. With an extract (`readAnalysisExtract`, § 5.2) the dataset tables follow the checks card, inside a `.print-report` wrapper (gotcha #27).

**One price per page.** `AnalysisDetailBody` resolves the price once — one `GET /api/quote/[ticker]`, else `priceAtAnalysis` in the result's currency, else none — and passes the same value to the position banner, the recap row, `<ValuationChecksCard>` and the analyst panel's gates. On the fallback each says so ("Price at analysis", "checks against the price at analysis (live quote unavailable)"); the banner shows a P&L only on a live price in the position's currency (`sameCurrency`), else a line saying why (`pnlUnavailable`); the fair-value cards and the recap show the distance from the price only on a price in the report's currency, else a note naming both (`recapCurrencyMismatch`); with no price at all a one-line note replaces the card. `priceAtAnalysis` stores no currency of its own and is read in the report's. Before 2026-10-29 the banner and the summary each fetched their own quote, and a failed one left the page with no card at all; the same day the cards still weighed a quote in pence against a report in pounds, off by 100.

### 2.5 Rendering a report — `components/report/*`

- **`<ReportBody markdown={...} />`** is the single place the `react-markdown` + `remark-gfm` + `prose prose-invert prose-report prose-sm max-w-none` recipe lives; don't hand-roll it in a component (it was once duplicated across three components with a violet/sky accent inconsistency). **`@tailwindcss/typography` is required** for any `prose*` class to do anything: without the plugin the classes are silent no-ops (gotcha #22). The custom variant `report` (`prose-report`, `tailwind.config.ts` → `theme.extend.typography.report`) adds a top rule and spacing on every `h2`, which gives the AI's `## N. Title` headings their section-divider look. Strip the JSON block (and the markers) with `stripJsonBlock()` before rendering any saved report — never a hand-written regex: the block is now at the end, and older reports have it at the top.
- **`<ReportShell>`**: the live panel and the saved detail page render the same layout: masthead (company/ticker/date) → `MethodBadges` → `FairValueCards` → `ReportBody` (inside a `.card`) → `RecapTable` → static disclaimer footer. Don't reintroduce a local `RecapTable`/`UpsideBadge`/inline card JSX in a new consumer. `RecapTable` uses the `.rtable` utility (AGENTS.md › Dense tables → cards below `sm`), so it collapses to cards on phones; its first `<td>` (scenario name) uses `.rcell-block` as the card title.
- **Print / PDF**: "Download PDF" calls `window.print()`, no PDF library. `app/print.css` (imported once in `app/layout.tsx`) scopes light-theme overrides to `.print-report` (the wrapper `<ReportShell>` renders); app chrome uses Tailwind's `print:hidden` in JSX. Upside/downside (emerald/red) and the violet accent are **kept** in print by product decision; only the neutral slate surfaces are inverted, via targeted selectors on the slate utility classes rather than a blanket `* { color: black }`. `break-inside: avoid` on cards/tables and `break-after: avoid` on `h2` prevent mid-page splits. Two traps: (1) a page hosting `<ReportShell>` must mark its OWN chrome `print:hidden` (`/analyze` printed its header, search and MoS as a first page until `analyze-client.tsx` did); (2) content OUTSIDE `.print-report` gets none of the overrides (gotcha #27): the analyst critiques are legible in print only because `ReportBody` carries its own `print:text-slate-900`. A sibling block meant for the PDF gets a conditional `print:hidden` (shown only with content) and keeps its controls `print:hidden`.

### 2.6 The valuation is always position-blind (hard invariant)

**Never inject the user's portfolio position (WAC, shares, P&L) or a prior estimate into the Deep Value or analyst prompts**; the run metadata (`aiSettings`, `language`) does not enter them either. The valuation's worth is its independence: anchoring it to what the user paid or to a previous run is motivated reasoning on a money decision, and it contaminates the saved report used for later comparison. A position-aware "Review Position (AI)" path existed and was removed for exactly this reason (July 2026); do not re-add a `reviewContext`/`prevFv`/`wac` field to `/api/ai/deep-value`. The two legitimate needs are met **outside** the valuation:

- **Hold / add / exit reasoning → the Advisor** (`/advisor`), which reads positions + saved analyses read-only and never emits a valuation.
- **Estimate evolution over time → a deterministic diff, not the AI.** `computeEvolution(prev, curr)` in `lib/report/evolution.ts` compares two saved analyses on the intrinsic scale (each grossed up with its own MoS), base scenario only; the consensus sub-row appears only when both saves carry analyst values. `computeEvolutionChain(analysesNewestFirst)` returns one `Evolution` per adjacent pair, so `EvolutionDiff` shows the whole save history. If a "how did X change" feature can be pure arithmetic over stored numbers, compute it — don't ask the model.

### 2.7 Reading a saved valuation — ruler, verdict, consensus

`ValuationRuler` / `ComparisonTable` / `axisFraction` / `Triple` live in `components/report/valuation-ruler.tsx`; `getVerdict` / `Verdict` / `VERDICT_BADGE` / `VERDICT_TEXT` in `lib/report/verdict.ts`; `grossUpToIntrinsic` in `lib/report/valuation.ts`. Extracted from `components/analyses-list.tsx` so `watchlist-client.tsx` could reuse the same ruler and consensus UI. **`/analyses` is the reference implementation — regression-test it after touching these modules.**

- **Zones encode the decision**: emerald buy (≤ buy target), amber watch (buy target → FV), neutral rich (≥ FV). `getVerdict(price, buyTargetBase, intrinsicBase)` → `buy | watch | over`, styled via the static `VERDICT_BADGE` / `VERDICT_TEXT` maps (never assemble class strings: AGENTS.md › Tailwind dynamic classes require static strings).
- **Signal-reliability flag** (`lib/report/signal.ts`, pure): `getSignalStrength(price, {bear,base,bull})` on the intrinsic scale returns `low | moderate | clear` — `low` when the base-vs-price edge is small relative to the bull↔bear cone (`signal/dispersion < ~0.15`). Both lists render a muted "weak signal" pill (`weakSignalLabel`/`weakSignalHint`) next to the verdict when `low`. Self-calibrating, pure arithmetic over the stored triple; it stops a fair-value ≈ price null result from reading as a confident call (§ 4, the design lesson).
- **Verdict and zones prefer the consensus** once an analyst lens has run: `buyTargetBase`/`fvEdge` (the `getVerdict` inputs and the zone props of `ValuationRuler`) come from `consensusTriple(a)`/`meanTriple(...)`, else from the base analysis. The base analysis's own tick (white) stays at its own value, so a disagreement is visible. **Change the zone props and `getVerdict`'s inputs together**, or the price dot sits in a zone that contradicts the badge.
- **One verdict basis**: `verdictBasis()` and `watchlistBuyTarget()` (`lib/report/latest-analysis.ts`) serve /analyses, watchlist, exit signal and digest alike; a latest save without values falls back to `latestAnalysisWithValues()`.
- **One price rule**: `comparablePrice(price, quoteCurrency, analysis)` (same file) passes the quote only in the analysis's currency (`sameCurrency`, § 5). On a mismatch there is no verdict, no price dot, no "Under FV" match, no exit signal (`getExitSignal`) and an `unknown` digest status (`digestPriceRead`), each with a note naming both currencies (`verdictCurrencyMismatch`; the email says it in Italian); an open position's P&L needs the price in the lots' own currency. Values are formatted in the analysis's currency, the price in its own. Added 2026-10-29: every one of these compared the raw quote, so a GBp quote against a GBP analysis read a hundredfold. `getQuote` turns a missing currency into `USD` (`lib/yahoo-client.ts`): a quote Yahoo returns without one is compared as dollars. The display has the opposite trap: `Intl.NumberFormat` accepts `GBp` as `GBP`, so a pence quote is written as pounds (`£7,000.00` for 7,000 pence; verified 2026-10-29, not fixed).
- **The axis stays on the intrinsic scale**; a `level` state (`"intrinsic" | "buyTarget"`, owned by the caller — `TickerGroup`, `WatchlistCard`) only moves marks and values, and `ComparisonTable` is controlled by the same `level` — don't reintroduce local toggle state.
- **Marks carry no inline value labels** (they collide when FV, lenses and consensus sit close): values live in a legend row under the bar (`● price · │ FV/Buy target · ╎ per analyst lens · ◆ consensus`). `markers.analysts` is `{key,label,value}[]`, one tick per lens that ran, colored via the static `ANALYST_TICK_BG` (skeptic slate, optimist fuchsia, quality indigo). Position a mark with `` `${pct}%` ``; a label that must stay inside the bar uses `left: clamp(16px, ${pct}%, calc(100% - 16px))`.
- **`currency?`** is optional: the watchlist passes the analysis's currency (the quote's when the analysis has none), `/analyses` doesn't.
- **Watchlist card** (`components/watchlist-client.tsx`, `WatchlistCard`): the same ruler and table, fed by `latestAnalyses: Record<string, SavedAnalysis>` (the latest saved analysis per ticker, consensus via `presentAnalysts`/`meanTriple`). **Its buy target uses the MoS of the watchlist item, not the analysis's**: the analysis (or the consensus) gives the intrinsic value, the item's `mosPercent` re-derives the buy target. **The verdict phrase names its source** — `belowBuyTargetPhrase`/`aboveBuyTargetPhrase` "(analysis)" vs the `…ConsensusPhrase` "(consensus)" keys, picked by whether a consensus exists, because the base buy target and the consensus can sit close but different (10.20 vs 10.10). The email digest mirrors it from `item.consensusBase !== null`.

### 2.8 History — the classic engine was removed

The classic `lib/valuation/*` engine (sector detection + DCF/DDM/EV-EBITDA + scenario presets) was removed: Deep Value picks the method inside its prompt and no client-side scenario sets are sent. The lite-analysis engine that enforced sector → method rules in a system prompt went with the Compare page.

## 3. The analyst panel

### 3.1 Pattern — multi-lens fresh-context verifiers

After a Deep Value analysis is **saved**, the detail page (`components/analyst-panel.tsx`) runs up to three independent second-opinion passes — **skeptic** (red team), **optimist** (constructive bull case), **quality** (long-term durability) — each streaming from `/api/ai/deep-value/verify` with an `angle` param (default `"skeptic"`).

- **One route, one parameterized builder**: `buildAnalystSystemPrompt(angle, …)` / `buildAnalystUserPrompt(angle, …)` share the JSON block, the authoritative-price guard and the MoS clause, and differ only in persona and focus (`ANGLE_CONFIG`). Rule of Three: three lenses → one builder + a registry, not three near-duplicate prompts. `AnalystAngle`/`ANALYST_ANGLES` are canonical in `types/analysis.ts`.
- **Shared structural checks**: `ANALYST_STRUCTURAL_CHECKS` is interpolated into all three lenses (EV→equity bridge completeness and minorities, method↔narrative coherence, same-basis comparables, scenario vs sensitivity, anchoring and MoS), because a real review found all three missing the same structural defects.
- **Non-prescriptive**: a lens commits to its own valuation and says whether the report's fair value should move, but issues no trade call more prescriptive than the report ("buy at €X" when the report concludes "hold").
- **Fresh context**: each lens is a distinct call that receives only the finished report (`stripJsonBlock`), not the original conversation; clean-context critique beats self-critique.
- **Each lens commits to its own valuation**: critique first after `<!--critique-->`, its own bull/base/bear (same schema, MoS-adjusted, `mosPercent` passed in so it compares directly) in the JSON block LAST. A lens block has `units` and a `bridge` per scenario but no `sensitivity` and no `dividends` (2026-10-11: a lens judges the report's number, it does not redo it, and three lenses would triple the cost; pinned by `__tests__/deep-value-prompts-contract.test.ts`). The route gates on `createStreamGate(CRITIQUE_START_MARKER)` in the single-phase branch and in turn 2 of blind-first, with the same flush + `[verify] critique marker never arrived` warning and the same fence closing on `max_tokens` as § 2.1, always before any route note (a note written inside the open fence was hidden with it, 2026-10-29); `__tests__/verify-route.test.ts` covers both branches. Effort: the same `xhigh` floor, in the route and in the panel's initial state; `X-AI-Settings` on the response.
- **Client state per slot**: `AnalystSlot` owns `critique`/`status`/`abortRef`; while streaming it renders through `stripTrailingOpenJsonFence`; on completion it PATCHes `{ angle, critiqueMd, fairValue*, valuationMethod, resultJson, blindJson? }` (§ 2.3) and turns `done` (the Re-run button) only once that save has settled, failed or not: a reload while it was in flight once lost a whole lens (2026-10-29; `__tests__/analyst-panel.test.tsx`). On demand only, one button per lens, never auto-run: each pass is an Opus xhigh + web-search call (cost, and 8+ minutes on the 2026-10-29 run). The live `/analyze` panel runs no review.
- **`max_tokens: 64000` + `stop_reason` tracking**: 16k truncated real critiques mid-word.
- **Authoritative price**: the route calls `getQuote(ticker)` (best-effort) and the system prompt marks the live price authoritative, so the lens does not "correct" it with a stale web quote.
- **The base report's gates reach every lens call**: `buildBaseGatesText` recomputes them (from `resultJson`, else the report's last fence; with the grounding extract when there is one) and `formatGatesForPrompt` appends them to the single-phase prompt, the degraded fallback and turn 2 of blind-first, so the lens addresses concrete FAILs. When the quote fails they are computed on `priceAtAnalysis` and the prompt says it is NOT the current price.
- **Persistence**: skeptic reuses the legacy `reviewMd`/`reviewFairValue*`/`reviewValuationMethod`; optimist and quality have `optimistCritiqueMd`/`optimistFairValue*`/`optimistValuationMethod` and the `quality…` equivalents; each lens also has `*BlindJson` and `*ResultJson`. `ANALYST_COLUMNS` (`lib/report/consensus.ts`) maps `angle` → columns (`critique`, `bull/base/bear`, `method`, `blind`, `result`), the single source shared with reads.
- **Consensus is N-way and centralized**: `lib/report/consensus.ts` (pure) — `consensusTriple(a)` / `meanTriple(triples)` / `presentAnalysts(a)` / `analystTriple(a, angle)` — the mean of the base analysis and every lens that ran; `null` when none ran (it would equal the base). It replaced `(base + reviewer) / 2` averages copy-pasted across four files. The disagreement Δ% is the same at intrinsic and buy-target level (MoS scales both). `Triple` lives in `lib/report/valuation.ts` (pure), re-exported from the ruler so server code can share it.
- **Adversarial Skeptic + no-praise rule**: the Skeptic's job is to BREAK the thesis — a **kill price** or an explicit statement that it can't build one. All lenses share an unconditional "do not praise" rule: (a) the errors, (b) the single most fragile assumption, (c) the one number that flips the conclusion; agreement is valid but never replaces (b)/(c). Distilled from a live review where all three lenses opened with "good work".

### 3.2 Blind-first two-turn pattern (Grounded only) — `verify/route.ts`

When a model's opinion must be independent of a conclusion it will later read, run the SAME `system` prompt (it describes both phases up front) across two turns:

1. **Turn 1 (blind)** — `buildAnalystBlindUserPrompt`: the data without `reportMd` (the absence IS the point). Streamed to a sink, never forwarded until parsed. Its output order is unchanged: JSON first, then a short rationale. The system prompt's closing rules (disclaimer, nothing before `<!--critique-->`, nothing after the fence) are scoped to Phase 2 in this mode: unscoped, they gave Phase 1 two opposite orders (2026-10-29).
2. **Turn 2 (reconcile)** — `messages: [...turn1.messages, {role:"user", content: reconcilePrompt}]`, the full transcript replayed **verbatim** (an orphaned `tool_use`/`server_tool_use` block is a 400). The reconcile prompt echoes the blind numbers and states the rule that does the anti-anchoring work: a value may change ONLY by citing a fact or arithmetic error NOT available in turn 1 — "the report argues X" is not a reason. Turn 2 writes `<!--critique-->`, the critique, the FINAL JSON (with `revisions`) last.

**Relabel the fence server-side; never ask the model for two different fences.** Both turns use the same ` ```json ` template; the route relabels turn 1's fence to ` ```json-blind ` before forwarding it. That label does not match the ` ```json\n ` regex, so `parseDeepValueJson` (last fence) and `stripJsonBlock` resolve to turn 2's final block, while `pickBlindCommitment` (`lib/ai/blind-commitment.ts`) takes the FIRST valid fence of turn 1's text. `__tests__/parse-deep-value-json.test.ts` asserts the non-collision ("parseDeepValueJson resolves to the FINAL block when both a blind and a final block are present").

**Degrade, never pay a third turn**: if turn 1's JSON doesn't parse (or turn 1 was refused), turn 2 runs the ORIGINAL single-phase prompt and the blind commitment is not persisted.

**What persists**: `*BlindJson` (the Phase-1 commitment) next to the final `*FairValue*` scalars, which remain what consensus, ruler, watchlist and digest read. The final JSON — `revisions[].reason` and the Skeptic's `killPrice` included — is stored in `*ResultJson` and read back on reload: the blind card shows the blind and final kill price, the cited revisions and the final `kill_price` gate; a lens with no blind commitment (single-phase) gets `<AnalystFinalCard>` with the same fields and `FINAL_CARD_GATES` (kill price, scenario order, probabilities, cross-check, method family, horizon, bear vs price). The blind gate list drops `sensitivity_center` and `dividend_coverage`, which a lens block never declares (§ 3.1). During a live run only a full final triple feeds the card (`hasFullTriple`); a re-run that fails before its blind phase parsed restores the stored critique and result (an abort comes only from a newer run of the same lens, which owns the slot from then on).

## 4. Prompt rigor — `ANALYTICAL_RIGOR_BLOCK`

`buildDeepValueSystemPrompt` injects `ANALYTICAL_RIGOR_BLOCK` (module-level const, between the scenario step and the output step): **19 mandatory checks** distilled from real reviewer findings. Checks 1-12 (latest quarter; dated guidance only; guidance vs estimate; normalized EBITDA; scenarios reconciled to the stated sensitivity; base case re-derived at the base driver, not a stale TTM; same-basis comparables + anti-selection-bias + structural-discount test; complete EV→equity bridge with minorities, varied per scenario; method↔narrative coherence; **anchor the valuation lever to something independent of the price — the market-implied read is a control that reports the GAP, never the input**; MoS adequacy; internal-consistency linter) verify internal consistency. Checks 13-18 (unconditional, Quick AND Grounded) verify assumption validity, added after a live review (Iren S.p.A.) passed all twelve with a fatal basis mismatch: bear-case validity, bull/bear horizon symmetry, dividend coverage by FCF, ROIC-vs-WACC discipline, a mandatory structurally different second method with a numeric reconciliation, explicit probabilities. Check 19 (2026-10-29), sensitivity honesty: the 3×3 grid is recomputed, never interpolated, and its centre is the base intrinsic value. Checks are conditional where relevant, so they no-op where they don't apply.

The Quick-mode prompts are locked by the golden `__tests__/deep-value-prompts-quick-identical.test.ts`: any change to a shared builder must leave it green, and a regeneration is a deliberate, read diff (its header says when the last one happened and what the next allowed change is).

**Design lesson**: telling a model to "anchor X and cross-check against Y" can make it game the letter — an earlier version made the market-implied cross-check the anchor and produced base fair value ≈ price by construction. Prompt rules reduce this, never guarantee it; the structural cure is a deterministic anchor computed in code plus a post-check that recomputes the model's own bridge (§ 5.1, on every analysis; the dataset gates need Grounded mode). The weak-signal flag (§ 2.7) is the other always-on read. The rule of the series since 2026-10: **the model declares, the code verifies**.

## 5. Grounded mode and the deterministic checks

Optional mode on `/analyze`: the user pastes typed blocks (income statement, balance sheet, cash flow, historical multiples, forward estimates, peer comps), saved on confirmation as a financial dataset (§ 5.2). `lib/grounding/*` (pure) — `merge.ts`/`basis.ts`/`anchors.ts`/`reconcile.ts`/`postcheck.ts`/`prompt-format.ts`/`schema.ts` — computes historical multiple stats, a 3×3 valuation grid, the market-implied multiple (a **control**, never an input), basis reconciliation, gates and reconciliation warnings. Validated on two live runs (Iren S.p.A., Webuild/WBD.MI).

- **Extraction is streaming, `max_tokens: 64000`** (`app/api/ai/grounding/extract/route.ts`): the API rejects non-streaming requests above a `max_tokens` threshold before generating, which once made every block fail at once; adaptive thinking counts toward the cap even on a transcription, and 16k let it truncate the JSON mid-object. Nothing is forwarded to the client. The model is pinned (Sonnet 5.5, medium effort) and ignores the stored default, with structured output (`extractionOutputFormat`); the Zod parse stays the boundary. The per-kind schemas live in `lib/ai/grounding-extract-schema.ts` (a Next route file may only export handlers), which lets a test keep the prompt example and the schema key-for-key identical.
- **Basis reconciliation (`lib/grounding/basis.ts`) — the highest-ROI piece.** The historical multiples (provider basis, P) and the pasted income statement (statement basis, S) need not share an EBITDA/EV definition. `computeBasisReconciliation(extract)` estimates `kE = EBITDA_P/EBITDA_S` and `kB = EVbridge_P/EVbridge_S` per year — direct from `marketCap`/`enterpriseValue` columns, else inferred from `evSales×revenue`/`pe×netIncome`/`pb×totalEquity` — aggregates to a median and returns `confidence: "high"|"low"|"unavailable"`. **Never silently assumes `kE=1`.** `toProviderBasis()` (a bare multiple) and `bridgeToProviderMultiple()` (equity value + statement-basis bridge, scaled by `effectiveKb` before dividing by kE) are the only doors into `percentileOf(...)` against the raw series. Injected FIRST in the anchors section, worded as binding ("computed in code — NOT your judgment").
- **The gates** run on every analysis, with or without a paste: § 5.1.
- **Injection split — system carries rules, user carries data.** The system builders take `grounding` only as a presence flag for `GROUNDED_RULES_BLOCK` (web search rescoped, not removed; the Estimates trap; units/currency; anchors are facts; basis reconciliation is binding; raw text wins; horizon). The user builders render the numbers via `formatGroundingForPrompt()`. Quick mode (`grounding` and `blindFirst` omitted) stays byte-identical — check the golden FIRST when touching these builders (§ 4).
- **Currency guard — `sameCurrency()` (`lib/grounding/currency.ts`).** Trimmed and case-sensitive (`GBp`, pence, is not `GBP`), empty or null never matches. `computeMarketImplied`/`computeImpliedExpectations` return `null`, not a wrong number, on a mismatch between the dataset (pasted or researched) and the quote, with a `currency_mismatch` warning: a research dataset reported in `GBP` against a `GBp` quote has no market-implied read; in `checkValuationBridges` a result whose currency differs from the quote's leaves every price gate "unavailable — currency mismatch" and `expectedValue` null. A price in one currency divided by an EBITDA in another is the worst bug class here; never remove the guard.
- **Lenses re-read grounding from the DB and get anchors, not the raw paste.** The verify route reads the extract and the dataset's stored warnings by `analysisId` through `readAnalysisGrounding` (§ 5.2; never from the body: 100-200KB per lens) and calls `buildGroundingPromptContext(blocks=[], extract, ...)` — `blocks` empty on purpose, since the line-item detail would triple input cost over three passes. The base report's gates go to every lens call (§ 3.1).
- **The card**: `<ValuationChecksCard>` shows the checks under the report on the live panel and on the saved page, for every analysis; it is rendered as a sibling of `<ReportShell>`, hence gotcha #27.

### 5.1 Gates — every analysis, with or without a dataset

`checkValuationBridges(result, mosPercent, price, quoteCurrency, extract | null)` (`lib/grounding/postcheck.ts`) recomputes each scenario's bridge (arithmetic within 1%, MoS applied) and returns the gates in display order; `checkReportStructure(reportMd)` adds `sections_present`, appended by the card. Each gate is `pass` / `fail` / `unavailable`, and **a gate that cannot verify reads unavailable, never pass**. "No dataset" means no extract or one with no financial rows (`datasetOrNull`): the basis is `EMPTY_BASIS`, there is no market-implied multiple, and the dataset gates say "no dataset". The price is the one the page shows (§ 2.4). Intrinsic values are fair values grossed up by the MoS (§ 1.3).

| Gate | Reads | Rule | Unavailable when |
|---|---|---|---|
| `basis_same` | kE, base bridge multiple | pass: same basis, or the multiple within 5% of the same-basis median; fail: within 5% of the raw provider median only (the Iren signature) | no dataset, not an EV/EBITDA bridge, kE unknown, no base multiple, or it matches neither median |
| `horizon_consistent` | the three `driverYear`s | pass: all equal | a scenario without one |
| `bear_breaks_price` | bear intrinsic, price | pass: bear < price | currency mismatch, no bear or price |
| `multiple_vs_market` | base implied multiple vs market-implied, statement basis | fail: within 3% (the model copied the price) | no dataset, not an EV/EBITDA bridge, either multiple unavailable |
| `trailing_forward` | base `driverYear` vs latest FY, LTM-equivalent multiple | informs only, never fails: pass when trailing or when an LTM-equivalent percentile exists | no dataset, not an EV/EBITDA bridge, year missing, forward with no LTM equivalent |
| `netdebt_trajectory` | latest FY net debt, FCF, DPS × shares; bridges with `driverYear` = FY+1 | fail: a bridge's net debt below 95% of `netDebt − (FCF − dividends)` | no dataset, no bridge, an equity bridge (`equity bridge · net debt 0`) or an unknown method family, inputs missing, no scenario on FY+1 (` · long-horizon driver` when one is beyond) |
| `roic_vs_wacc` | `assumptions`, base multiple vs same-basis median | fail: ROIC < WACC with a multiple ≥ the median | no dataset, not an EV/EBITDA bridge, ROIC/WACC or multiple/median missing |
| `probabilities` | the three probabilities | pass: sum within 0.02 of 1 | any missing |
| `cross_check` | `crossCheck.intrinsicPerShare` vs base intrinsic | pass: delta ≤ 25% | no cross-check, no base |
| `cross_check_basis` | `crossCheck.bridge.multiple`, kE | `basis_same` on the cross-check's bridge (a DCF primary has no multiple: Webuild) | as `basis_same` on the cross-check's method and bridge, plus no cross-check |
| `scenario_order` | the three intrinsic values | pass: bear < base < bull, strictly | a scenario missing |
| `method_distinct` | method families of `method` and `crossCheck.method`, each anchored at the start of the name (`EV/EBITDA (peers)` is EV/EBITDA, `Peer EV/EBITDA` is none) | fail: same family (`EV/EBITDA` vs `EV/EBITDA (peers)`) | no cross-check, unknown family |
| `sensitivity_center` | the 3×3 grid, base bridge intrinsic | pass: centre within 1% of the base and the central row and column monotonic | no grid or no base bridge |
| `dividend_coverage` | year-1 base DPS × latest diluted shares vs mean of the last three reported FCFs (fewer when fewer are reported; the detail reads `mean FCF(Ny)`) | pass: a non-payer (`dividends: null`, before any data check) or ratio ≤ 1; fail: ratio > 1 or mean FCF ≤ 0 | no dataset, currency mismatch, path/FCF/shares missing |
| `units_match` | `units` vs the dataset's | fail: different | no dataset, either undeclared |
| `sections_present` | the report Markdown, `## N.` (also `．` or `)`) for N = 1…10 | fail lists the missing numbers | never |
| `kill_price` | lens `killPrice`, `killPriceNote` | pass: a number; fail: null without a note | null with a note (an honest "cannot build one"). Lenses only: present when the key is present, even `null` |

A fail on `basis_same`, `bear_breaks_price`, `roic_vs_wacc`, `scenario_order` or `sensitivity_center` shows red, any other fail amber. `trailing_forward` re-expresses a forward driver's multiple on the last reported EBITDA (`impliedMultipleLtm`/`impliedPercentileLtm`/`growthWedgePct`); `cross_check_basis` also enables `PostCheck.crossCheckBridge`, the cross-check's own arithmetic. `expectedValue` is display-only. **The EV/EBITDA gates read only an EV bridge on EBITDA** (`isEvOnEbitda`): an EV/EBITDA method, or a DCF on FCFF whose driver label names EBITDA. The pasted history, the basis reconciliation and the market-implied multiple are all EV/EBITDA, so `basis_same`, `multiple_vs_market`, `trailing_forward` and `roic_vs_wacc` read `not an EV/EBITDA bridge` on any other base bridge, `cross_check_basis` on any other cross-check bridge, and no implied multiple is computed for them; `netdebt_trajectory` needs an EV bridge of any kind. Before 2026-10-29 they read every bridge: a DDM cross-check on a per-share DPS yielded a meaningless implied multiple with a dataset (seen on a real Quick run). Without a dataset the card draws no implied multiple (nothing to rank it against), and the cross-check row only for its arithmetic. Every card names a gate through `GATE_LABEL_KEY` (`valuation-checks-card.tsx`); the codes are for the prompts and the tests (2026-10-29: the lens cards printed them; `__tests__/analyst-panel.test.tsx` asserts none reaches the screen). The lens lists drop the gates a lens block cannot pass (§ 3.2).

### 5.2 The financial dataset — `types/dataset.ts`, `lib/datasets/*`

- **One row per confirmed dataset** (`FinancialDataset`). A paste is born at "Analyze with this data", never at "Prepare data" (an abandoned paste leaves no row); a web dataset at the end of a research run (§ 5.3); a merged one from the two (§ 5.3). Columns: `userId`, `ticker` (normalized), `origin` (`paste` / `web` / `merged`), `currency`/`units`/`coverageLabel`, `dataJson` (the extract, rows and sources included, plus `datasetMeta`, which only the server writes; a paste's comes from the client validated by shape with `groundingPayloadSchema`), `blocksJson` (the paste: the raw text the Deep Value prompt reads, the lenses get none; null for web), `warningsJson`, `researchJson` (`ResearchMeta` of a web or merged dataset, null for a paste; a malformed one reads as `research: null` and the row stays). The merge itself never runs in the browser: the extraction route does it (below). `Analysis.datasetId` points to it (`ON DELETE SET NULL`: deleting an analysis keeps its dataset); the migration `add_financial_dataset` rebuilds `Analysis` (AGENTS.md § Prisma 7 + Turso). `groundingJson` is no longer written (since 2026-10-30 `POST /api/analyses` drops the key); older rows keep it. Only the warnings of the run that made the dataset are stored (`DATASET_WARNING_CODES` in `lib/datasets/parse.ts`: `block_extract_failed`, `value_conflict`, `meta_currency_conflict`, `meta_units_conflict`, and since the research `source_unverified`, `source_unknown_id`, `value_ignored_secondary`, `ebitda_derived`; `POST /api/datasets` and the research route drop the rest): every valuation recomputes the others from the extract and its own quote. The same list validates the read, and a stored warning outside it makes `parseStoredDataset` return null for the whole row: a writer that stores a new code widens the list first.
- **Provenance.** A financials row carries `sources`: one `DataSource` (`kind`, `url`, `title`, `asOf`, `blockId`, `verified`) per statement (`income`/`balance`/`cashFlow`, by `STATEMENT_FIELD_KIND`) plus a `mixed` flag per statement when a second block filled one of its fields; a multiples, estimates or peer row carries one `source`. A blob saved before parses with every source `null` and `mixed` false (the row schemas' defaults; `sources` defaults through a factory, since Zod 4's `.default(obj)` copies only the top level).
- **Merge at the server** (`mergeExtractedBlocks(results, blockOrder)`): the merge builds its own rows and never writes an input row (a row spread is shallow: a written `sources` would reach every row sharing it). It keeps the first value it sees, and the route sorts the results into `blockOrder` first (`orderByBlockOrder`), so the first block in the editor wins a field and the first block that fills any field of a statement owns it. A conflict names both blocks by kind and 1-based position among the blocks sent (`blockOrder`, empty blocks excluded): `revenue: 1000 (income_statement #1) vs 990 (income_statement #3)`. Nothing parses the detail.
- **Retry of one block.** The extraction request carries `blockOrder` (every block sent for the dataset, in editor order), the blocks to run and `priorResults` (validated); the route merges prior and fresh results in `blockOrder` (a block sent again replaces its earlier result, even when it fails again) and answers 502 only when no block has a result. A failure reads `<kind> #<position>` (written and read only in `lib/grounding-warnings.ts`; the editor shows, and the dataset stores, the position in its own list, empty blocks counted), so even a lens prompt, which gets no blocks, names the statement. The editor also re-sends any block with no result that did not fail (added or edited since), or the merge would silently miss it, and rebuilds the warning of every failed block it did not re-send: the route only knows this request's failures, and until 2026-10-30 a retry that fixed one of two failed blocks dropped the other's warning from the preview and from the saved dataset (`__tests__/grounding-input.test.tsx`). After a retry the saved blocks are the editor's current non-empty blocks.
- **Routes**: `POST /api/datasets` (paste: 201 `{ id }`; merged: 201 with the preview bundle, § 5.3; `web` is a 400), `GET /api/datasets/latest?ticker=&maxAgeDays=` (204 when none), `GET /api/datasets/[id]` (404 for another user's; its client helper `fetchDataset` has no caller yet, the e2e authorization pair uses the route). `lib/datasets/store.ts` (server-only) scopes every read to the user; `parseStoredDataset` (`lib/datasets/parse.ts`, pure) returns `null` on any malformed column.
- **One reader**: `readAnalysisExtract(userId, analysis)` — the dataset by `datasetId`, else the legacy `groundingJson` through `parseStoredExtract` — for the detail page; `readAnalysisGrounding` adds the stored warnings, for the verify route. The Deep Value POST takes `datasetId` (400 `dataset not found` / `dataset ticker mismatch`) and rebuilds the context from the row (blocks, extract, stored warnings deduplicated by `code|fiscalYear|detail`); `POST /api/analyses` checks owner and ticker the same way. The prompt never sees the provenance: `formatExtract` skips `sources`, `source` and `datasetMeta`.
- **UI.** `<DatasetSection>` on `/analyze` looks up the user's latest dataset of the last `DATASET_REUSE_MAX_AGE_DAYS` (7) days, aborting and checking the ticker so a late answer for the previous one is dropped. With one (used or not: a dataset saved for a run that then failed is offered too), it opens on its date and origin, `<DatasetTables compact>` (last three years), its stored warnings (plus the currency against the quote), "Use this dataset" (no AI call) and "Refresh data" (the editor, seeded with the dataset's blocks unless the local draft differs from them, text included: an unsaved draft wins and is announced, `chooseStartingBlocks`). Reuse lives only here, one click after a look at the numbers. `<GroundingInput>` is the editor: "Analyze with this data" saves the dataset and hands `{ id, extract }` up. `<DatasetTables>` (one table each for income, balance sheet, cash flow, multiples and estimates, shown only when it has a value, nothing at all when none has; years in columns, the first row "Source" with a `<SourceChip>` per year: 📋 paste, 🌐 host, unverified, +1, —; no peer table: peers show in the preview's aggregates) shows in the preview, the reuse view and the saved page.

### 5.3 Research (stage 1) — `app/api/ai/research`, `lib/ai/research-*.ts`, `lib/datasets/merge-sources.ts`

Without a paste, the financials used to come from the web inside the valuation run and survived only as prose. The research stage collects them first, as data with a source on every row, and saves them as a `FinancialDataset` with `origin: "web"` (2026-10-30). No UI yet (2026-10-30): the route and `researchDataset(ticker, aiSettings?)` (`lib/dataset-client.ts`) exist, `/analyze` does not call them, and no client helper posts a merge.

- **The run**: `POST /api/ai/research { ticker, aiSettings? }` → quote (name, exchange, trading currency; never the price, position-blind) → `researchAiSettings` (Sonnet 5.5 `high` when the resolved provider is Anthropic, whatever Claude model the default names; the user's DeepSeek model at `high` on DeepSeek, never `max`; the override lives only in the body, and only its model counts: its effort and thinking are accepted and ignored) → one `runStreamWithToolLoop` call, nothing streamed to the client, `max_tokens: 64000`, adaptive thinking, top-level `cache_control` on Anthropic (each `pause_turn` resume re-sends the fetched pages), `DEEP_RESEARCH_MAX_TOOL_ITERATIONS` (on Claude it counts the `pause_turn` resumes), `{ fetchBudget: RESEARCH_MAX_FETCHES }` (8). Missing provider key → 503 «research requires the Anthropic/DeepSeek API key». `maxDuration = 300`: one request. `ResearchMeta.model` is the resolved model, `servedBy` the one that answered through the Sonnet 5.5 refusal fallback (null when the resolved one did, and on a row researched before 2026-10-30's fix: until then the fallback showed only in the `[tool-loop]` log).
- **Tools** (`buildResearchTools(model)`, `lib/ai/client.ts`): Claude gets `web_search_20260209` (`max_uses: 30`) and `web_fetch_20260209` (`max_uses: 8`, `max_content_tokens: 40000`, which does not limit a PDF: the prompt allows three); never declare `code_execution` next to them (their dynamic filtering runs it internally). DeepSeek gets `CUSTOM_WEB_SEARCH_TOOL` and `CUSTOM_WEB_FETCH_TOOL` (`lib/ai/web-search-tool.ts`, DeepSeek's Fetch API: `# title` + Markdown cut at 60,000 characters with a closing line; every failure, the budget refusal included, starts with `FETCH FAILED`). The loop runs a turn's searches in parallel (the Search API allows 5 requests per second per account; a 429 reaches the model as a `tool_result` and no log prints it: serializing them waits for one to be seen, 2026-10-30) and its fetches one at a time (per-domain QPS); only an executed fetch spends the budget, one past it gets the budget message, and a route without `fetchBudget` (Advisor, earnings, valuation) answers any `web_fetch` with it, never a throw.
- **The contract** (`lib/ai/research-prompt.ts`, `lib/ai/research-schema.ts`): primary sources first (IR press releases, then filings, data providers only for multiples), no target prices, five fiscal years (three at least), `fiscalYear` = the year the fiscal year ENDS, units and reporting currency declared once, `sources` (≤ 30, `id` ≤ 10) with `sourceIds` per statement on financials rows and one `sourceId` on the others, a short log, then the JSON fence LAST, read with `lastJsonFence` (`lib/report/parse-deep-value-json.ts`, the valuation's own reader). The prompt's example and the schema are pinned key for key (`__tests__/research-contract.test.ts`); the model's `meta` is `researchOutputMetaSchema`, apart from `researchMetaSchema` (`lib/datasets/parse.ts`), which reads the stored `ResearchMeta`. The preprocess drops a bad source entry (URL not absolute http(s), id not 1-10 characters) instead of failing the run — its rows read as `source_unknown_id` —, keeps the first entry of a repeated id, maps an unknown `kind` to `other`, nulls a free-text `asOf`, keeps 30 sources and drops financials rows with no figure; a missing nullable field reads null, free text is clipped. 502s: invalid JSON, or an answer whose every source entry the preprocess drops («Research returned an invalid dataset»: `sources` needs one), no financial rows («No financial data found»), iteration cap, `max_tokens`, refusal, a turn that ended on `tool_use`.
- **Verification** (`collectSeenUrls`, `lib/ai/transcript-urls.ts`): a cited URL is not an opened URL. A source is `verified` only when its normalized URL (origin + path, no query, no trailing slash, host lowercase) appears in a search or fetch RESULT of the transcript: `web_search_tool_result` / `web_fetch_tool_result` on Claude, the `tool_result` of a client `web_search` (its URL lines) or of a `web_fetch` that read a page on DeepSeek. Error blocks add nothing; a domain alone is not enough. A row whose sources are all unverified is kept (chip «unverified», `source_unverified` naming the URL, the URL in `ResearchMeta.unverifiedSources`); only sources a row cites count, an uncited entry of `sources` changes nothing. `blocksByCaller` counts the result blocks by type and `caller.type`: with dynamic filtering a search or fetch can run from code execution, and a URL seen only in code-execution output would read as unverified.
- **To a dataset** (`researchToDataset`, `lib/ai/research-to-dataset.ts`): ids resolve to web `DataSource`s (a fresh copy per row), every series sorted by ascending year (anchors and gates read the last element), two rows of one year fused field by field (`value_conflict` above 1%; a statement the second row fills from another URL is marked `mixed`, chip "+1"), an unknown id warned once per year, peer tickers normalized, `meta.notes` into `ResearchMeta.notes`. **EBITDA the company does not publish is computed here, never by the model** (owner, 2026-10-30, after real runs on ENI and Coca-Cola found no group EBITDA): `ebitda = ebit + depreciationAmortization` on every row with EBIT and D&A and no EBITDA, named in one `ebitda_derived` info warning (the years); when D&A comes from another page than EBIT the income chip says "+1". `depreciationAmortization` is a cash-flow field of every financials row (`STATEMENT_FIELD_KIND`), stored as a positive amount whatever sign the page used (until 2026-10-30's fix a cost line printed negative was stored negative; only the sum took its absolute value), null on pastes (no extraction schema asks for it) and on datasets saved before (schema default). The prompt forbids the model any arithmetic (owner, 2026-10-30: "Never compute a figure from other figures", the full-year DPS as interim + final excepted), after DeepSeek derived an EBITDA from a ratio. The route saves with the run's own warnings, reads the row back (a row that would not parse is a 500 at once, not a missing dataset at the next reuse) and answers `ResearchResponse` (`types/dataset.ts`; `grid` null when no grid can be drawn) with `computeDatasetAnchors` (`lib/datasets/anchors-bundle.ts`), the one computation of basis, stats, grid, market-implied and their warnings shared with the extraction route and the merge.
- **Merge at the server** (`mergeDatasets(primary, secondary, ids?)`; `POST /api/datasets { ticker, origin: "merged", pasteDatasetId, webDatasetId }` → 201 `MergedDatasetResponse`, whose `research` is the web row's, null when that carries none): per STATEMENT × year, the paste's whole statement when it has any figure of it (the web's figures for it → `value_ignored_secondary` info, a > 1% divergence → `value_conflict` `"<field>: <a> (paste) vs <b> (web)"`), else the web's whole statement with its source and its `mixed` flag; multiples, estimates and peer rows whole from the paste when it has the year; `latestPeriodLabel` the later of the two, `fiscalYearEnd` the paste's else the web's. Known units are rescaled to the paste's (money and shares; per-share, multiples and percentages unchanged), rounded to 15 significant digits (until 2026-10-30's fix ×0.001 stored `7.3420000000000005` and printed it in the conflict details); a different currency (`sameCurrency`: two unknown ones are a conflict too) or an unknown unit is no merge (the paste alone + `meta_currency_conflict` / `meta_units_conflict`). The merged row stores the paste's warnings, the merge's, and the web's that still describe it (`secondaryWarningsKept`, since 2026-10-30's fix: before, a merged row lost them and stage 2 got a computed EBITDA or an unopened page with nothing saying so): `ebitda_derived` for the years whose income statement came from the web, one `source_unverified` per unverified URL a merged row still cites, and `research.unverifiedSources` narrowed to those URLs; the web's `source_unknown_id` and `value_conflict` stay behind, since neither names its statement. Both ids must be the user's (404), of one ticker (400) and of origin paste and web (400). The trap of the per-statement rule: `sharesDiluted` and `eps` belong to the income statement (`STATEMENT_FIELD_KIND`), so a paste with only revenue and EBITDA for a year drops the web's shares for it, and that year's market-implied read is missing (seen in the 2026-10-30 collaudo).

## 6. AI settings and the Anthropic integration

### 6.1 Anthropic integration

- **Model split** (route fallbacks; the user's stored default or a per-run override wins): `claude-opus-4-8` for Deep Value and the analyst lenses (`max_tokens: 64000`; effort floored at `xhigh`, § 2.1), `claude-sonnet-5-5` for the Advisor (`max_tokens: 16000`, `high`) and the earnings lookup (`medium`).
- **Thinking** from `buildThinkingParam()` (`lib/ai/client.ts`): `{ type: "adaptive" }` while the user's toggle is on (default); off → `{ type: "disabled" }` on Opus 4.8 / Sonnet 5 and `{ type: "between_tools" }` on Sonnet 5.5 (still adaptive at `xhigh`/`max`).
- **`"xhigh"` and `between_tools` are typed by the SDK** since the bump to `^0.133` (2026-10-12): `buildEffortConfig()`/`buildThinkingParam()` pass them with no cast. Don't add a cast for a value the SDK doesn't type yet: bump the SDK.
- **Sonnet 5.5 rejects non-default sampling params** (`temperature`, `top_p`, `top_k` → 400).
- **Web search**: `{ type: "web_search_20260209", name: "web_search" }` (dynamic filtering, current models); `web_search_20250305` for older ones.
- **Streaming**: `runStreamWithToolLoop()` (§ 6.2), `content_block_delta` + `text_delta`; `client.beta.messages.stream()` on Sonnet 5.5 for the refusal fallback.
- **`max_tokens` must budget thinking + web-search reasoning**, not just the visible answer: the Advisor at 4096 stopped mid-word on long Discovery replies (now 16000). It is a ceiling, not a target.
- **Surface `stop_reason: "max_tokens"` — never truncate silently.** Track it from `message_delta` and enqueue a visible note before closing; the Deep Value and verify routes also close an open JSON fence first (§ 2.1).
- **Surface `stop_reason: "refusal"` the same way.** A classifier can decline with HTTP 200 and little or no text (Sonnet 5.5: `cyber`, `bio`, `frontier_llm`, `reasoning_extraction`, `general_harms`). Streaming routes append a "declined" note; JSON routes answer a specific error. Branch on `stop_reason`, never on `stop_details` (can be `null`). A refused blind Phase 1 degrades to the single-phase review, and turn 2 starts without the refused transcript (an empty assistant turn is rejected as history).
- **Server-side refusal fallback on Sonnet 5.5** (2026-10-12): every `claude-sonnet-5-5` call goes through `client.beta.messages` with `betas: ["server-side-fallback-2026-07-01"]` + `fallbacks: "default"` (`usesServerSideFallback()`, applied inside `lib/ai/tool-loop.ts`). A `cyber` or `frontier_llm` decline is re-run on Claude Sonnet 5 inside the same call; `bio`, `reasoning_extraction` and `general_harms` are not retried and still reach the route as `refusal`. Not sent to Opus 4.8 / Sonnet 5 (no fallback for them), never to DeepSeek (no beta surface on its Anthropic-compat endpoint), Claude API only (Bedrock/Vertex/Foundry would need the SDK's client-side middleware). A `between_tools` request that falls back runs on Sonnet 5 with thinking disabled, server-side. **Who answered**: a `fallback_message` entry in `usage.iterations` (sticky-routed turns, served directly by the fallback model for ~1 h, carry no `fallback` content block) and the response's top-level `model`; the loop returns it as `servedBy` and the three streaming routes append a note naming that model (`fallbackNote()`, `lib/ai/fallback.ts`), which then lands in the saved text; the research route, which has no text, stores it as `ResearchMeta.servedBy` (§ 5.3). **Replay**: an assistant turn sent back as history goes through `prepareTurnForReplay()`, which drops the declining model's `thinking`/`redacted_thinking`/`tool_use`/unpaired `server_tool_use` blocks before the last `fallback` block; a turn without one is untouched. Covered by `__tests__/tool-loop.test.ts` + `__tests__/ai-fallback.test.ts`.
- **Route error status — SDK classes, not message text**: `routeErrorStatus()` (`lib/ai/error-status.ts`): 503 to `Anthropic.RateLimitError`, to any `Anthropic.APIError` ≥ 500 and to the Yahoo adapter's "rate limit" `Error`; 400 otherwise. Used by the six AI routes (Advisor, Deep Value, verify, extraction, research, earnings).
- **Advisor/Discovery verify a ticker is still listed** before recommending it: `Today is …` alone doesn't stop delisted suggestions (it once proposed RM.MI, delisted 2021). A prompt rule in both builders, not a guarantee; a deterministic `/api/quote` check per `[[TICKER]]` is not built.
- **`GROUNDING_RULES_BLOCK`** (`lib/ai/advisor-prompts.ts`, in both Advisor builders): current prices only from the LIVE PRICES block, never a historical `priceAtAnalysis` as current, and any cited cause/event/guidance web-verified with a date or labelled "unconfirmed" — added after the Advisor invented a dated story for a price move. Enabling web search is not enough: the requirement must live in the prompt.
- **Always inject the language** in both system and user prompt.
- **Prompt caching was evaluated and rejected** (prompt size, 2026-10-29: Quick system prompt 30,414 characters, rigor block 45%; ≈ 23,400 and 58% on 2026-10-11): single-user usage (~1 analysis a day) never sends a second request against the same prefix within the 5-minute TTL, so it would only pay the ~1.25× write premium. Revisit if usage changes (several users, Advisor turns closer than 5 minutes). **Two exceptions**: the research stage (§ 5.3), whose `pause_turn` resumes re-send the fetched pages seconds later; and the blind-first lenses, which set a top-level `cache_control` on turn 1 (Anthropic only: DeepSeek's proxy does not support it), since turn 2 re-reads the same prefix seconds later; turn 2 sets the same provider-gated breakpoint via `buildPromptCacheParam()` (`lib/ai/tool-loop.ts`). Check `cache_read` in the `[tool-loop]` usage log.

### 6.2 Multi-provider settings (model / effort / thinking)

Users pick, per call site (Deep Value, analyst panel, Advisor, earnings lookup), a model, an effort and thinking on/off: a global per-user default plus a per-run override on the three main panels.

- **Catalog** (`types/ai-settings.ts`): `AI_MODEL_CATALOG` — `claude-opus-4-8`, `claude-sonnet-5`, `claude-sonnet-5-5`, `deepseek-v4-pro`, `deepseek-flash` — each with `provider`, `efforts` (subset of `AI_EFFORT_LEVELS`) and `supportsWebSearch`. A retired id in `LEGACY_AI_MODEL_IDS` resolves to its successor (`normalizeAiModelId`; the map is empty since 2026-10-29); the AI routes and the settings PATCH validate through `aiModelIdSchema` (`lib/ai/ai-preferences.ts`): an unknown id is a 400, a stored one falls back to the route default. Both DeepSeek models expose `low`/`high`/`max` (as of the 2026-08-13 V4-Pro update DeepSeek maps medium and xhigh to high; verified against `https://api-docs.deepseek.com/guides/thinking_mode/` on 2026-08-24). `DEFAULT_AI_SETTINGS` = Opus 4.8 / high / thinking on.
- **Effort per call site steps DOWN, never up** (2026-10-29): `callSiteDefaultEffort(model, preferred)` returns the preferred level if the model supports it, else the nearest LOWER supported level (DeepSeek at `xhigh` → `high`, not `max`); it backs `clampEffort` (every route, Advisor and earnings included) and the selector's model change. `deepValueDefaultEffort(model, global)` = the higher of the global default and `xhigh`, through the same step-down: Deep Value and the lenses start at `xhigh` unless the global default is `max`.
- **Resolution**: `resolveAiSettings(userId, override, fallback)` — request override > stored `User.ai{Model,Effort,ThinkingEnabled}` > the route's fallback — then `clampEffort()`. The Deep Value routes pass an override without effort when the request has none, so the floor applies to the stored default.
- **DeepSeek peak/off-peak pricing** (`https://api-docs.deepseek.com/quick_start/pricing/`, 2026-08-24): off-peak 50% of peak since 2026-08-16; peak windows UTC `01:00–04:00` and `06:00–10:00`, Monday–Friday. `lib/ai/deepseek-pricing.ts` (`isDeepSeekPeakHour()` / `formatDeepSeekPeakWindows()`, pure, DST-aware) feeds a live badge in `<AiSettingsControl>`, re-checked every 60 s. DeepSeek's Search/Fetch REST APIs (`POST https://api.deepseek.com/v1/tools/search` / `/fetch`, same key, $0.75 per 1k successful requests) back the client-executed tool.
- **Claude Sonnet 5.5** (2026-10-11): `thinking: {type: "disabled"}` is a 400, so `buildThinkingParam(thinking, model, effort)` sends `between_tools` (accepted only at `high` or below) and stays adaptive at `xhigh`/`max`; it also rejects non-default sampling and forced `tool_choice`. The Grounded extraction and, on Anthropic, the research stage (`RESEARCH_AI_SETTINGS`) are pinned to it; Advisor and earnings use it only as the route fallback. Covered by `__tests__/ai-client.test.ts`.
- **Client construction** (`lib/ai/client.ts`): `getAiClient(model)` (one singleton per provider; DeepSeek is the same `@anthropic-ai/sdk` client with `baseURL` `https://api.deepseek.com/anthropic` + `DEEPSEEK_API_KEY`), `buildThinkingParam()`, `buildEffortConfig()`, `usesServerSideFallback()`, `buildWebSearchTools(model)`.
- **DeepSeek web search is client-executed** (gotcha #25): `buildWebSearchTools` returns `CUSTOM_WEB_SEARCH_TOOL` (`lib/ai/web-search-tool.ts`, standard function calling, DeepSeek's Search API, `count: 8`) for DeepSeek, the native `web_search_20260209` for Claude.
- **Shared tool loop** (`lib/ai/tool-loop.ts`): all six AI routes call `runStreamWithToolLoop()` / `runCreateWithToolLoop()`. For Claude the loop only resumes `pause_turn` and reports `servedBy`; for DeepSeek it executes `web_search` (and, for the research stage, `web_fetch` within `fetchBudget`, § 5.3) `tool_use` blocks and feeds `tool_result`s back until the model stops or `maxIterations` is hit. **Size `maxIterations` to the route's research depth**: Deep Value, verify, earnings and the research stage share `DEEP_RESEARCH_MAX_TOOL_ITERATIONS` (35, raised from 25 when the rigor checks pushed real DeepSeek runs into the cutoff; on Claude every `pause_turn` resume spends one, and a research run that runs out of them is a 502); `RECONCILE_MAX_TOOL_ITERATIONS = 4`. **Observed, unmitigated**: at DeepSeek `max` the model uses more rounds, so an earnings lookup can take 10+ rounds; that route has no per-run override. 8 search results with 600-800-character summaries make each round more productive. The loop returns `hitIterationCap` (gotcha #26), the full replayable `messages` transcript and the concatenated `text` (both used by blind-first), and logs `[tool-loop] round N usage: …` per round. It resumes `pause_turn` (Claude's server-side search pauses a turn after ~10 internal rounds) with the same `messages`, never a new user turn after a pause — before that, a paused turn returned a partial answer silently. DeepSeek's Anthropic-compat endpoint still documents no server-side search tool, so gotcha #25 still applies.
- **UI**: `<AiSettingsControl>` (`components/ai-settings-control.tsx`) inline on Deep Value, Advisor and the analyst panel (**one selector for all three lenses**; `AnalystSlot` already takes `aiSettings` as a prop if that ever changes); `<AiPreferencesModal>` (gear icon in `NavBar`) + `GET/PATCH /api/settings/ai` for the stored default. Each panel fetches the default on mount — no shared cache, fine at this scale.

## 7. Gotchas (numbered as in AGENTS.md)

13. **Claude non-streaming multi-text blocks.** With `client.messages.create()` and `web_search`, `content` often holds several `text` blocks: early reasoning between tool calls, the final JSON in the last one. `response.content.find(b => b.type === "text")` returns the **first** (wrong). Concatenate all text blocks and match on the joined string:
    ```typescript
    const allText = response.content
      .filter(b => b.type === "text")
      .map(b => (b as { type: "text"; text: string }).text)
      .join("\n");
    const match = allText.match(/```json\n([\s\S]*?)\n```/);
    ```
25. **A provider's server-side tool call can leak raw internal syntax into a text stream** if its Anthropic-compat translation fails to parse it. Reproduced in production with DeepSeek's server-side `web_search`, non-deterministically (`<｜DSML｜tool_calls>...` in visible chat text). Routes that gate pre-report text (Deep Value, verify) are shielded; routes that stream raw text (Advisor) are not. Fix: declare a standard function-calling tool and execute it yourself (`lib/ai/tool-loop.ts` + `lib/ai/web-search-tool.ts`). A spike that runs clean once or twice proves nothing for a route with no gate.
26. **A tool loop with no "marker never reached" failsafe fails silently.** Deep Value once buffered everything until its marker; when the DeepSeek loop hit `maxIterations` first, the stream closed with zero bytes and the client set `status: "done"` — no error anywhere. Three fixes together: size `maxIterations` to the route's research depth; always `flush()` the gate when the marker never came (both routes, with a `console.warn`); and treat an empty final response as `status: "error"` on the client, never `"done"`.
27. **A component rendered as a sibling of `<ReportShell>`, not inside it, gets no print-safe styling.** `app/print.css` scopes its overrides to `.print-report`; `<ValuationChecksCard>` sits outside it and reads darker in the PDF (a visual defect only manual testing catches). Nest a new post-report component inside `.print-report`, or give it explicit `print:` variants matching `print.css`.
28. **`runCreateWithToolLoop` reports `hitIterationCap`, resumes `pause_turn` and logs usage per round**, like its streaming sibling; it returns `{ message, stopReason, hitIterationCap, messages, servedBy }`. Before that, a loop out of rounds mid-`web_search` returned the last `tool_use` message as an answer and `/api/earnings` answered a generic `502 "AI returned no parseable result"` (production, 2026-08-24, DeepSeek). The route now answers a specific 502 ("ran out of web search rounds") and runs on `DEEP_RESEARCH_MAX_TOOL_ITERATIONS`.
29. **The parser returns `ParsedAnalystResult`: narrow with `hasFullTriple()` before any dereference** (§ 1.3). bull/base/bear may be missing; an incomplete triple shows `deepValueIncompleteJson` and saves null fair values and no `resultJson`. A malformed block still fails `JSON.parse` as a whole.
